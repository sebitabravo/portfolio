Chile tiene más de 90 volcanes activos. Es la segunda cadena volcánica más grande del mundo, después de Indonesia. Sernageomin hace el monitoreo oficial, pero cuando hay una emergencia, la información que llega a las comunidades es un desastre: grupos de WhatsApp, publicaciones de Facebook, llamadas. No hay una fuente única de verdad.

Los que viven en zonas de riesgo — agricultores, pobladores rurales, equipos de emergencia municipales — no tienen cómo reportar lo que ven en terreno. Esa información de primera mano se pierde o circula sin verificación.

Vulcania intenta resolver ese vacío. Es una plataforma de monitoreo volcánico comunitario que junta observaciones ciudadanas con datos verificados, centrada en el Volcán Villarrica.

## Dos modos, una app

La aplicación funciona en dos modos. El modo **Demo** usa datos simulados locales y no necesita nada más que el frontend corriendo. El modo **Completo** se conecta a Supabase para auth, base de datos y tiempo real. La transición es automática: `lib/app-config.ts` chequea si existen las variables de entorno de Supabase y, si no, activa demo.

Esto no fue un lujo. Fue la decisión que permitió que cualquiera pudiera clonar el repo y ver la aplicación completa sin configurar una base de datos, sin crear un proyecto en Supabase, sin tocar variables de entorno. `pnpm dev` y ya está.

En modo demo, los datos vienen de `lib/demo-data.ts`: un usuario predefinido con teléfono +56 9 8765 4321, alerta naranja para el Villarrica, tres puntos de encuentro precargados (Estadio Pucón, Escuela Quelhue, Club de Huasos), zonas de evacuación. Suficiente para mostrar la experiencia completa.

## El modal de emergencia

El componente `emergency-modal.tsx` es lo más interesante de la app. Cuando el nivel de alerta sube a naranja o rojo, un modal a pantalla completa bloquea todo y emite un patrón de sonido con la Web Audio API.

No usamos archivos de audio. Usamos osciladores de onda triangular generados en tiempo real: 880 Hz con pulsos cortos para alerta naranja, 440 Hz con pulsos más largos e intervalos más cortos para alerta roja. El sonido se reproduce en loop hasta que el usuario interactúa. Hay un botón `forceEmergency()` en desarrollo para probar el modal sin esperar una alerta real.

Los navegadores bloquean la reproducción automática de audio — necesitás interacción previa del usuario. La solución fue un handler de `click`/`touchstart` que inicializa el AudioContext y lo mantiene vivo con `setupAudioUnlock()`. Sin ese truco, el modal de emergencia sería mudo cuando más se necesita.

Las notificaciones de navegador usan `document.visibilityState`: solo disparan cuando la pestaña no está visible. Si el usuario está activamente mirando el mapa, no tiene sentido tirarle una notificación.

## Resultados

- **Plataforma PWA funcional** con demo online en producción, instalable y offline-first
- **Mapa interactivo en tiempo real** con datos sismológicos y capas de datos volcánicos
- **Chat comunitario** con sincronización instantánea vía Supabase Realtime
- **Sistema de alertas** con notificaciones push configurables por nivel de urgencia
- **Síntesis de audio** con Web Audio API para el modal de emergencia — osciladores generados en tiempo real, sin archivos de audio

## Lecciones aprendidas

- **Supabase Realtime simplifica drásticamente WebSockets.** Lo que antes requería un servicio dedicado ahora son suscripciones declarativas. Broadcast, presence y postgres changes en un solo producto.
- **Las PWA son infravaloradas.** Instalabilidad, offline-first y notificaciones nativas sin pasar por app stores. Para herramientas de emergencia, que el usuario no tenga que instalar nada es una ventaja decisiva.
- **Row Level Security es traicionero.** La configuración inicial permitía que un usuario viera reportes de otro. Las políticas `USING` y `WITH CHECK` correctamente definidas por `user_id` delegaron la autorización a la capa de datos sin middleware complejo. Pero hay que testearlas como código.
- **Leaflet sobre Mapbox/Google Maps.** Más liviano, open source, y suficiente para datos geoespaciales de complejidad media. La importación dinámica con `next/dynamic` y `ssr: false` requiere baile inicial, pero vale la pena.
- **La normalización de teléfonos chilenos es un infierno necesario.** +569XXXXXXXX, +56XXXXXXXX, 9XXXXXXXX, 0XXXXXXXX — todas válidas. La función `normalizarTelefono()` maneja todas las combinaciones para que el login funcione sin importar cómo el usuario escriba su número.
