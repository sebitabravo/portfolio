Apuntes completos del curso Git Mastermind de INACAP. Cubre desde `git init` hasta flujos de trabajo colaborativos con pull requests.

## Qué cubre

- **Configuración inicial**: `git config` para email y nombre
- **Estados de archivos**: Untracked, Modified, Staged
- **Commits**: mensajes imperativos en inglés, atomicidad
- **Ramas**: creación, checkout, merge, push con `-u`
- **Remotos**: `git remote`, `git clone`, `git pull`
- **Historial**: `git log --oneline --graph`
- **Restauración**: `git reset` vs `git restore`
- **Buenas prácticas**: una tarea = una rama, pull request para mergear a main, `.gitignore`

## Lo que aprendí

Git no es solo comandos — es un modelo mental. Entender que los commits son snapshots, no diffs, cambia cómo pensás el historial. `git reset --hard` es destructivo y no debería ser el primer reflejo ante un error. Un `.gitignore` bien configurado desde el inicio evita commits accidentales de archivos sensibles.
